# User documentation, docs links in errors and a production README — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a ddev-sync section on docs.noix.dev. Every error the tool prints ends with a link to its troubleshooting entry, and the README shrinks to a production front page that points at the docs.

**Architecture:** Two repositories.
- **The engine (`/Users/noidee/_dev/ddev-sync`)** gets a slug registry (`src/ddev_sync/docs.py`), an optional `doc` on `DdevSyncError`, and one rendering rule for the three places errors reach the user. Errors without an explicit slug fall back to the area of the module that raised them.
- **The docs (`/Users/noidee/_dev/noix-docs`, default branch `develop`)** get the section, a troubleshooting page whose headings produce exactly the registry's slugs, a check script that keeps the two in step, and a build-time Docker Hub tag table.

**Tech Stack:** The engine as it is (see its CONTRIBUTING.md; gates: ruff, ruff format, mypy strict, pytest at 100 %). The docs: Astro 6 + Starlight 0.40, `starlight-links-validator`, Node ≥ 22.

**Spec:** `docs/specs/2026-10-27-user-docs-design.md`

**Source of truth for content:** `/private/tmp/claude-501/-Users-noidee--dev-ddev-sync/f40edbdf-bad4-4695-9af0-edb906cd7c17/scratchpad/ddev-sync-inventory.md`, an inventory of every command, flag, key, profile, endpoint setting and error, with file:line pointers. Where it and the code disagree, the code wins. Read the code at the pointer whenever you are unsure.

## Global Constraints

- **Language and public text.**
  - Docs, README, code comments and commits are in English.
  - Public text (README and docs) names what the user works with: DDEV, Docker, SSH, MySQL/MariaDB, rsync, and the frameworks Laravel, Symfony, WordPress, Drupal, TYPO3 and Shopware.
  - It never names how the tool is built: no "Python", "click", "pydantic", "uv" or "Alpine".
- **No invented keys or flags.** Every key, flag, default and command in the docs exists in the code. Never document these, because they do not exist: a config key `steps`, `jump`, `proxy`, `--no-color`, `--debug`, or any `DDEV_SYNC_*` engine env var.
- **Docs link base:** `https://docs.noix.dev/ddev-sync/reference/troubleshooting/`. A link is that base + `#<slug>`. The line rendered after an error is exactly `More: <link>`, indented as described in Task 1.
- **Slug rule.** A slug is the GitHub-style slug of its heading text on the troubleshooting page:
  - lowercase;
  - drop every character that is not `a-z`, `0-9`, a space or `-`;
  - turn each space into `-`.

  So headings use no underscores, no backticks and no punctuation that would change the slug.
- **Ownership.**
  - The engine's registry in `src/ddev_sync/docs.py` is the list of slugs.
  - The docs keep a copy in `src/data/ddev-sync-doc-slugs.json`.
  - `scripts/check-ddev-sync-anchors.mjs` fails if any slug in the copy has no heading on the page.
- **Docs structure.**
  - Section root: `src/content/docs/ddev-sync/`, with `getting-started/`, `guide/` and `reference/`.
  - Page frontmatter carries `title`, `description` and `sidebar.order`, as the Printy pages do.
  - Register the topic in `astro.config.mjs` with label `ddev-sync` and link `/ddev-sync/getting-started/introduction/`. Add a hub card in `src/content/docs/index.mdx` and an entry in the docs `README.md` tree, all following commit `bc3c060` (Printy).
- **Discord invite:** `https://discord.gg/sHcvJfXhq`.
- **Docker images:** `noixdev/ddev-sync` and `noixdev/ddev-sync-endpoint`. They have versioned tags only and no `latest`; the docs say so.
- **Branches.**
  - Engine work goes on branch `docs/user-docs`, cut from `main`, in a worktree.
  - Docs work goes on branch `docs/ddev-sync`, cut from `develop`, in `/Users/noidee/_dev/noix-docs`.
  - Commits are conventional and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Nothing is pushed.

## Review Focus

1. **A multi-line error message.** Many messages span several lines, and step errors are printed line by line under `FAIL`. The link must come once, after the last line, never inside the message. Test it in Task 1 (`test_the_link_follows_a_multi_line_message`).
2. **An explicit slug typo at a raise site.** It must fail loudly in the test suite and never print a dead link. `DdevSyncError(..., doc="typo")` raises `ValueError` at construction. Because coverage is 100 %, every raise site runs in some test, so a typo cannot ship. Test it in Task 1 (`test_an_unknown_slug_is_refused`).
3. **An interrupt (exit 130) or a click usage error (exit 2).** Neither gets a link; they are not failures to look up. Test it in Task 1 (`test_an_interrupt_carries_no_link`).
4. **Docker Hub returning more tags than one page, or being unreachable at build time.** The table follows `next` until it ends. On any fetch error it renders the fallback link, and the build still succeeds. Check it in Task 8 (Step 3).
5. **A heading renamed on the troubleshooting page.** Every error that links to it would 404. The anchor check fails the docs `check` script. Check it in Task 7 (Step 3: rename one heading, see the check fail, revert).

- Produces, in `ddev_sync/docs.py`:

  - `AREAS: tuple[str, ...]` — the area slugs, in page order:
    `command-line`, `configuration`, `targets`, `connection`, `preflight`, `database`, `files`, `env`, `sanitize`, `setup`, `deployer`, `docker-endpoint`, `init`, `profiles-and-features`, `add-on`.
  - `ENTRIES: tuple[str, ...]` — the entry slugs listed in Task 2's table.
  - `TOPICS: frozenset[str] = frozenset(AREAS + ENTRIES)`
  - `def doc_url(slug: str) -> str` returns `TROUBLESHOOTING_URL + "#" + slug`. It raises `ValueError(f"unknown docs topic {slug!r}")` when the slug is not in `TOPICS`.
  - `def doc_link(error: BaseException) -> str | None`. The first match wins:
    1. `error.doc`, if set;
    2. the area of the innermost traceback frame whose module starts with `ddev_sync.`, through `_MODULE_AREAS`;
    3. the area of the error's class, through `_CLASS_AREAS`;
    4. otherwise `None`.

    It returns `None` for `SyncInterrupted`.
  - `_MODULE_AREAS: tuple[tuple[str, str], ...]` — module-prefix → area, longest prefix first:
    - `ddev_sync.config.targets` → `targets`; `ddev_sync.config.deployer` → `deployer`; `ddev_sync.config` → `configuration`
    - `ddev_sync.ddev` → `configuration`; `ddev_sync.engine.plan` → `configuration`
    - `ddev_sync.transport.deployer` → `deployer`; `ddev_sync.transport.ssh` → `connection`
    - `ddev_sync.operations.preflight` → `preflight`; `ddev_sync.operations.database` → `database`
    - `ddev_sync.operations.files` → `files`; `ddev_sync.operations.s3` → `files`
    - `ddev_sync.operations.env` → `env`; `ddev_sync.operations.exec` → `setup`
    - `ddev_sync.operations.sanitize`, `.fake`, `.catalog`, `.placeholders` → `sanitize`
    - `ddev_sync.profiles` → `profiles-and-features`; `ddev_sync.features` → `profiles-and-features`
    - `ddev_sync.cli.init` → `init`; `ddev_sync.cli` → `command-line`
  - `_CLASS_AREAS` — `ConfigError` → `configuration`, `TargetError` → `targets`, `DeployerError` → `deployer`, `ProfileError` and `FeatureError` → `profiles-and-features`.
- Produces, in `errors.py`: `DdevSyncError.__init__(self, *args: object, doc: str | None = None)`.

  - Subclasses keep working unchanged.
