# env.pull Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A project lists variable names in `env.pull`, every `db` sync copies their remote values into the local env file, and a Docker stack can allow this once with `DDEV_SYNC_EXPORT_ENV: all`.

**Architecture:** The endpoint learns `all` and records values it had to skip. A new `operations/env_pull.py` reads the remote env file once per run and turns it into text ready for the local file. Preflight refuses what cannot be pulled, and the `env` step writes the rest behind a masked diff.

**Tech Stack:** POSIX sh (busybox, Alpine) in the endpoint; Python engine with pytest (100 % coverage gate); integration and matrix suites against real containers; noix-docs (Astro/Starlight) in `~/_dev/noix-docs`.

**Spec:** `docs/specs/2026-11-04-env-pull-design.md`

## Global Constraints

- Name rule: `[A-Za-z_][A-Za-z0-9_]*`, not starting with `DDEV_SYNC_`.
- Never pullable, as `ConfigError` at plan time: the five names `database.env_map` resolves to (`DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD`, `DATABASE_HOST`, `DATABASE_PORT` where it sets none), `DB_URL`, `DATABASE_URL`.
- Precedence: `env.set`, then `env.pull`, then `env.default`.
- Slugs: `env-pull-variable-missing`, `env-pull-value-has-a-line-break`, `env-pull-no-example-file`.
- Handover format stays v1. Skipped names line: `DDEV_SYNC_SKIPPED=NAME,NAME`, only when there is one.
- Endpoint log: `handing over N variables to the sync session`, plus `, skipped M with a line break` when M is not zero. Names never appear in it.
- Masked diff line: `NAME=***`. No pulled value in a log, dry run, plan detail, notice or error.
- Code, comments, specs and docs in English. `_parse_env` and how a mounted `.env` is found stay unchanged.

## Review Focus

- A `.env` with a multi-line quoted value before a pulled name: the continuation lines must not be read as assignments. Pinned in Task 2.
- Running the sync twice: the second run changes nothing and does not prompt. Pinned in Task 3.
- Pulling into a file created from `.env.example` when `env.set` and `env.default` change nothing else: the file must still be created. Pinned in Task 3.
- Answering no at the prompt: no file is created and the existing one is untouched. Pinned in Task 3.
- `DDEV_SYNC_EXPORT_ENV: all` with a variable whose name is not a shell name, such as `my.var`, and a PEM key beside it: the endpoint starts, and neither stops it. Pinned in Task 1.

    ```python
    @dataclass(frozen=True)
    class RemoteValues:
        path: str                 # the file that was read
        text: dict[str, str]      # name -> right-hand side, ready for the local file
        missing: list[str]        # not on the remote
        multi_line: list[str]     # has a line break
        references: list[str]     # raw `.env` values that refer to another variable

    def read_remote_values(context: ExecutionContext, names: Sequence[str]) -> RemoteValues: ...
    def encode_for_env_file(value: str) -> str: ...
    def raw_assignments(contents: str) -> tuple[dict[str, str], set[str]]: ...  # text, multi-line names
    def check_pull(context: ExecutionContext) -> None: ...   # raises OperationError
    ```
